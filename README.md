# 旅トク — 秋田発・国内の宿セールまとめ

毎月1回旅行する人が「いま何のセールが走っていて、次はいつ来るか」を1画面で見るためのサイト。
宿を主役に、航空券と新幹線・高速バスも拾う。**LLMもAPIキーも使わない。**

## 何をしているか

1. **セール告知の記事を集める** — TRAICY / airstair / sky-budget のRSSと、
   Googleニュース検索RSS（1クエリ1キーワード。ORを入れると結果が壊れる）。
2. **公式ページを直接読む** — 楽天トラベル・一休.com・Yahoo!トラベルは
   素のHTTPで開催中のセール名が読める。
3. **毎月の定番をカレンダーにする** — 5と0のつく日など、日付が決まっているものを今月の日付に直す。

結果は `docs/deals.json` に入り、`docs/index.html`（依存なしの1ファイル）がそれだけを読んで描く。

## 取れる社・取れない社

素のHTTPでセール名まで読めるのは **楽天トラベル・一休.com・Yahoo!トラベル** の3社だけ。

| 社 | 状態 | 理由 |
|---|---|---|
| じゃらん | 読めない | 特集バナーがJavaScript描画で、HTMLにセール名が入らない |
| JAL | 読めない | 素のHTTPは403（WAF）。ブラウザでしか開けない |
| ANA | 読めない | キャンペーン一覧の固定URLが無く404になる |
| JTB・るるぶ | 読めない | セール名の位置が回ごとに変わる |

**一休.com と Yahoo!トラベルは GitHub Actions のIPからだと 403 を返す。**
自宅の Mac から素のHTTPで叩けば通るので、取れなかった回は前回読めた内容を残し、
サイト側に「◯月◯日時点」と添える（空で上書きすると「セールが消えた」ように見えるため）。
最新にしたいときは手元で `更新.command` を叩く。

読めない社は黙って落とさず、サイト下部に公式ページへのリンクとして出す
（`sim_plan_watch` の `mode: "manual"` と同じ考え方）。
これらのセールも、記事側（TRAICY等）には載るので新着告知には出てくる。

## 混ざり物を落とす条件

集めた1,400本のうち、セール告知として残るのは200本ほど。落としているのは：

- **宿1軒だけの広告記事** — 「【楽天トラベルセール】◯◯県「宿名」が今だけ特別価格に！」の形。
  毎日十数本流れてくるので、これを入れると一覧が埋まる。
- **増便・就航・発売終了** — セール語は入るが値段が安くなる話ではない。
- **海外路線だけの話** — 国内旅行が主役のため。「国内」と併記されていれば残す。
- **旅行以外の楽天サービス** — 楽天モバイル・楽天カードのクーポン記事。
- **まとめ記事の切れ端** — 丸数字や貼り付け事故の英数字IDが入った見出し。

## サムネイル

**Googleニュース経由のリンク（全体の9割）は元記事URLに戻せない。** 短縮URLの base64 にも
リダイレクト先にも元URLが入っておらず、Googleの内部APIを叩くしかないので諦めている。

なので2本立て：

- **元記事に直接リンクしているもの**（TRAICY・airstair・sky-budget）は記事ページの `og:image` を使う。
  1回の実行で新しく取りに行くのは25件まで。取れた画像は `deals.json` に残して次回以降使い回し、
  「見に行ったが無かった」URLも覚えておいて二度は叩かない。
- **残りはサービス色のタイルを生成する。** 種別の絵文字（🏨✈️🚅🧳）＋割引率＋サービス名。
  外部への通信が要らず、リンク切れの空箱も出ない。タイルの中だけ「最大1万2000円」→「最大1.2万円」と縮める。

画像が消えていた場合は `onerror` でタイルに差し替わる。

## 並び順

点数の合計で決める。新しさ（7日以内+40）＋秋田・東北で使える（+20）＋全国規模（+15）
＋割引率が書いてある（+10）＋種別（宿+12）＋締切が3週間以内（+10）。

「秋田・東北」の印はエリア名（秋田・東北・岩手…）が見出しに出たときだけ付ける。
羽田・大阪のような路線名まで拾うと「東京〜金沢が9000円」が秋田印になってしまった。

## 行き先さがし（旅行アドバイザー）

`docs/places.json` に温泉地・エリアを120か所（全47都道府県）持たせている。
1か所につき **タグ**（温泉／秘湯／雪／海／離島／街歩き／絶景…）、**見ごろの月**、
**秋田からの距離感**（日帰り／1泊／遠征）を書いてある。

サイト側で「行った」「行きたい」を登録すると、まだ入れていない場所を点数順に6件出す。

- 行きたい場所とタグがどれだけ重なるか（最大35点）＋「〈銀山温泉〉と同じ温泉・雪」と理由を出す
- まだ行っていない県（+12）／今月が見ごろ（+18）／来月（+8）
- 近場を優先なら 日帰り+18・1泊+12、遠出もありなら遠征+8
- **その土地のセールが今出ていれば +25。** 地名そのものが見出しにあれば「いまセール中」、
  県名どまりなら「山形のセールあり」と区別する。県名を同じ扱いにすると、
  山形の宿のセール1本で山形県の全温泉地が「セール中」になってしまった。

記録は **そのブラウザの localStorage** に入る（Mac と iPhone では別々になる）。
移すときは「書き出す」で出た文字列を、別の端末で貼って「読み込む」。

**じゃらんの宿検索は keyword を Shift_JIS で渡さないと文字化けする。**
UTF-8で渡すと `驫?螻ｱ貂ｩ豕?` になって0件になる。ブラウザ側で変換するには
変換表がまるごと要るので、`collect.py` が実行のたびに `places.json` の
`jalan_q` に変換済みの文字列を入れておく（楽天は UTF-8 のままでいい）。
行き先を足すときは名前だけ書けば、次の実行で検索キーが埋まる。

## ANA・JALのセール開始をメールで知らせる（ana_alert.py）

ANA・JALの国内線タイムセールと国内ツアー（航空券＋宿）のセールが始まったら1通送る
（ファイル名は ana_alert.py のままだが JAL も見ている）。
**この Mac の launchd（`com.miffy.anaalert`、8:40／12:40／16:40／20:40）で動かす。**
Gmailのパスワードを GitHub Secrets に置きたくないため。メール設定は他のツールと同じ
`config_unified.json` の `email_settings` を借りる（場所は gitignore した `alert_local.json`）。

- ANAの公式ページは一覧の固定URLが無いので見ない。クラウドが集めている告知
  （公開サイトの `deals.json`）から、`sources.json` の `alerts` に書いた条件で拾う。
- **国際線・楽パック経由・「安く乗る方法」系の解説記事は除外。**
- **1回のセールで予告→開始→開催中と3日ほど記事が続くので、知らせたら10日間は黙る。**
  6〜9月のデータで再現すると、実際の3回のセール（6/28・7/24・8/25）にちょうど1通ずつで、
  6/28は「まもなく開始」の予告の時点で知らせられていた。
- 初回は基準を作るだけで送らない。送信に失敗した回は既読にせず、次の回にもう一度送る。
- 締切は「8月31日まで」だけでなく「8/31まで」も読む。
- **JALは一般販売の1週間ほど前に「開催決定」の記事が出る**（9/1決定→9/8会員先行→9/9一般）。
  開始日がまだ先なら件名を「JAL国内線タイムセール：9月8日から開催」にする。
  5〜9月の再現では JAL国内線2回・JALツアー3回に、それぞれちょうど1通。
- ジャルパックの記事は見出しに「JAL」と入らないことがあるので、`must` は「どれか1つ」。
- 「国内航空券＋宿泊」が国内線とツアーの両方に当たって2通にならないよう、国内線側は宿泊・パックを除外。
- 条件を後から足したときは、その条件だけ初回扱い（いま出ている古いセールでは送らない）。

```bash
python3 ana_alert.py --dry-run   # 送らずに判定だけ
python3 ana_alert.py --test      # 直近のセールで試しに1通送る（状態は変えない）
```

別の航空会社も見たいときは `sources.json` の `alerts` に1つ足せばいい。

## 壊さないための蓋

- 取得先の半分以上が失敗した回は書き込みごと中止する。
- セール告知が1件も取れなかった回は前回の内容を残す。
- `updated` 以外が前回と同じなら書き込まない（空コミットが6時間ごとに積み上がるため）。

## 動かし方

```bash
python3 collect.py          # 集め直して docs/deals.json を更新
```

`更新.command` をダブルクリックすると、集め直してGitHubへ反映するところまで走る。
自動更新は `.github/workflows/update.yml`（6時間ごと、Secrets不要）。

集め先を足したいときは `sources.json` を触る。コードは触らなくていい。
